## 1. Общие сведения

### 1.1. Назначение

Корпоративный чат-бот «Михалыч» для мессенджера MAX (VK Teams / Mail.ru Agent API). Предназначен для автоматизации внутренних процессов компании Онланта: поиск сотрудников, доступ к корпоративным ресурсам, информирование об отпусках, отображение паролей Wi-Fi и прочие сервисные функции.

### 1.2. Целевая аудитория

Сотрудники компании Онланта, использующие мессенджер MAX.

### 1.3. Платформа

- **Мессенджер:** MAX (протокол Bot API MAX / VK Teams Bot API)
- **Язык реализации:** Python 3.11+
- **Фреймворк:** aiohttp (async HTTP)
- **Режим работы:** Long Polling (с возможностью переключения на Webhook)

### 1.4. Глоссарий

| Термин | Описание |
|--------|----------|
| MAX | Мессенджер (ранее VK Teams / ICQ New) |
| Callback | Ответ на нажатие inline-кнопки (callback_data) |
| Inline-кнопка | Кнопка под сообщением бота |
| Long Polling | Режим получения обновлений через периодические запросы к серверу |
| Webhook | Режим получения обновлений через входящие HTTP-запросы от сервера |

## 2. Архитектура решения

### 2.1. Компоненты

```
┌─────────────────────────────────────────────┐
│              MAX Messenger API               │
└──────────────────┬──────────────────────────┘
                   │ HTTPS (Bot API)
┌──────────────────▼──────────────────────────┐
│              Bot Application                 │
│  ┌─────────────────────────────────────┐    │
│  │          Event Router               │    │
│  │  (commands, callbacks, messages)    │    │
│  └──────┬──────┬──────┬──────┬────────┘    │
│         │      │      │      │              │
│  ┌──────▼┐ ┌──▼───┐ ┌▼────┐ ┌▼──────────┐ │
│  │ Auth  │ │ Menu │ │Search│ │ Resources │ │
│  │Module │ │Module│ │Module│ │  Module   │ │
│  └───────┘ └──────┘ └─────┘ └───────────┘ │
│                                             │
│  ┌─────────────────────────────────────┐    │
│  │        Config / JSON Data           │    │
│  │  (resources, messages, wifi, etc.)  │    │
│  └─────────────────────────────────────┘    │
│                                             │
│  ┌─────────────────────────────────────┐    │
│  │       User State Manager            │    │
│  │   (in-memory / Redis session)       │    │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

### 2.2. Управление состоянием пользователя

Каждый пользователь имеет состояние (state), хранимое в оперативной памяти (dict) с возможностью миграции на Redis. Состояния:

| Состояние | Описание |
|-----------|----------|
| `IDLE` | Начальное состояние, до авторизации |
| `AUTHORIZED` | Пользователь авторизован, отображено главное меню |
| `SEARCH_EMPLOYEE` | Ожидание ввода фамилии сотрудника |
| `RESOURCES_PAGE` | Просмотр ресурсов компании (с номером страницы) |

### 2.3. Формат callback_data

Все callback-данные кнопок имеют единый формат:

```
action:param1:param2
```

Примеры:
- `start` — кнопка «Начать»
- `menu` — возврат в главное меню
- `search_employees` — поиск сотрудников
- `resources:1` — ресурсы компании, страница 1
- `resources_prev:1` — предыдущая страница ресурсов
- `resources_next:1` — следующая страница ресурсов
- `vacation` — хочу в отпуск
- `wifi_password` — показать пароль Wi-Fi
- `manager_menu` — подменю руководителя
- `counterparty_report` — экспресс-отчет по контрагенту
- `help_sib` — помощь СИБ (пауза)
- `upload_training` — загрузить тренировку (пауза)
- `ping_pong` — пин-понг (пауза)

| FR-006 | Ресурсы компании | Постраничное отображение ссылок на ресурсы (5 на страницу) |

| FR-008 | Показать пароль Wi-Fi | Отображение актуального пароля Wi-Fi |
| FR-009 | Руководителю | Подменю с функциями для руководителей |
| FR-010 | Экспресс-отчет | Ввод ИНН контрагента и получение отчёта |
| FR-011 | Модули на паузе | Помощь СИБ, Загрузить тренировку, Пин-понг — показывают заглушку |

### 3.2. Правила отображения кнопок

- Inline-кнопки располагаются **вертикально** (каждая кнопка — отдельная строка).
- Кнопки-ссылки (url) открывают внешний ресурс.
- Кнопки навигации (callback) вызывают действие внутри бота.
- Кнопка «🏠 Главное меню» всегда последняя в списке.

### 3.3. Правила обработки текстовых сообщений

- Если пользователь находится в состоянии `SEARCH_EMPLOYEE`, текст интерпретируется как фамилия.
- В остальных состояниях текстовое сообщение игнорируется (или бот предлагает воспользоваться меню).

## 4. Модуль авторизации

### 4.1. Сценарий: Команда /start

**Триггер:** Пользователь отправляет `/start`

**Действия бота:**

1. Отправить сообщение:
   ```
   👋 Привет! Я — MAX-версия Михалыча. Корпоративный чат-бот компании Онланта.

   🔐 Для начала работы мне нужно вас авторизовать.

   ✅ Нажмите кнопку «Начать», чтобы продолжить.
   ```

2. Показать inline-кнопку:
   ```json
   {
     "type": "callback",
     "text": "Начать",
     "callbackData": "start"
   }
   ```

3. Установить состояние пользователя: `IDLE`

### 4.2. Сценарий: Нажатие кнопки «Начать»

**Триггер:** Callback `start`

**Действия бота:**

1. Зарегистрировать пользователя (сохранить user_id, timestamp авторизации).
2. Установить состояние: `AUTHORIZED`.
3. Отправить главное меню (см. раздел 5).

### 4.3. Повторная команда /start

Если пользователь уже авторизован и снова вводит `/start`:
- Бот сбрасывает состояние и показывает приветственное сообщение заново (позволяет «перезапустить» бота).

## 6. Модуль «Поиск сотрудников»

### 6.1. Сценарий: Запрос поиска

**Триггер:** Callback `search_employees`

**Действия бота:**

1. Отправить сообщение:
   ```
   🔍 Поиск сотрудников

   Введите фамилию сотрудника:
   ```
2. Показать кнопку: `🏠 Главное меню`
3. Установить состояние: `SEARCH_EMPLOYEE`

### 6.2. Сценарий: Ввод фамилии

**Триггер:** Текстовое сообщение в состоянии `SEARCH_EMPLOYEE`

**Валидация входных данных:**

| # | Правило | Описание | Сообщение об ошибке |
|---|---------|----------|-------------------|
| V-001 | Обрезка пробелов | `strip()` по краям перед проверкой | — |
| V-002 | Минимальная длина | >= 2 символов после strip | `❌ Фамилия слишком короткая. Минимум 2 символа.` |
| V-003 | Максимальная длина | <= 50 символов после strip | `❌ Фамилия слишком длинная. Максимум 50 символов.` |
| V-004 | Допустимые символы | Только буквы (кириллица + латиница), пробел, дефис. Регулярное выражение: `^[а-яА-ЯёЁa-zA-Z\s\-]+$` | `❌ Фамилия содержит недопустимые символы. Используйте только буквы, пробел и дефис.` |

**При успешной валидации:**

1. Выполнить поиск по справочнику сотрудников (в текущей реализации — по JSON-файлу `data/employees.json`).
2. Поиск — нечувствительный к регистру, по вхождению подстроки в фамилию.
3. Если найдены результаты — отобразить список (макс. 10 результатов):
   ```
   ✅ Найдено сотрудников: N

   👤 Иванов Иван Иванович
   📧 ivanov@onlanta.ru
   📱 +7 (999) 123-45-67
   🏢 Отдел разработки
   ─────────────────
   👤 ...
   ```
4. Если не найдено:
   ```
   😔 Сотрудник не найден.

   Попробуйте ввести другую фамилию или вернитесь в главное меню.
   ```
5. Показать кнопки:
   - `🔍 Искать ещё` (callback: `search_employees`)
   - `🏠 Главное меню` (callback: `menu`)

### 6.3. Структура данных сотрудника

## 7. Модуль «Ресурсы компании»

### 7.1. Сценарий: Просмотр ресурсов

**Триггер:** Callback `resources:N` (где N — номер страницы, начиная с 1)

**Действия бота:**

1. Загрузить список ресурсов из `data/resources.json`.
2. Вычислить пагинацию:
   - Размер страницы: **5 ресурсов**
   - Всего страниц: `ceil(total_resources / 5)`
   - Текущая страница: параметр N
3. Отправить сообщение:
   ```
   📚 Ресурсы компании (Страница {N}/{total_pages})
   ```
4. Показать кнопки:
   - **Кнопки-ссылки** на ресурсы текущей страницы (тип `url`)
   - **Кнопки навигации:**
     - `⬅️ Предыдущая` — если текущая страница > 1 (callback: `resources:{N-1}`)
     - `➡️ Следующая` — если текущая страница < total_pages (callback: `resources:{N+1}`)
   - `🏠 Главное меню` (callback: `menu`)

### 7.2. Правила пагинации

| Условие | Отображение кнопок навигации |
|---------|------------------------------|
| Страница 1 из 1 | Нет кнопок навигации |
| Страница 1 из N (N > 1) | Только `➡️ Следующая` |
| Страница K (1 < K < N) | `⬅️ Предыдущая` и `➡️ Следующая` |
| Страница N из N (N > 1) | Только `⬅️ Предыдущая` |

### 7.3. Структура данных ресурса

```json
{
  "id": 1,
  "title": "Интранет",
  "url": "https://intranet.onlanta.ru",
  "description": "Корпоративный портал"
}
```

```json
[
  [{"type": "url", "text": "🔗 Интранет", "url": "https://intranet.onlanta.ru"}],

  [{"type": "url", "text": "🔗 Jira", "url": "https://jira.onlanta.ru"}],
```

## 14. Нефункциональные требования

### 14.1. Производительность

| # | Требование | Значение |
|---|-----------|----------|
| NFR-001 | Время ответа бота | < 2 секунды |
| NFR-002 | Поддержка одновременных пользователей | До 100 |
| NFR-003 | Интервал polling | 1 секунда |

### 14.2. Надёжность

| # | Требование | Описание |
|---|-----------|----------|
| NFR-004 | Обработка ошибок API | Автоматический retry с экспоненциальным backoff (3 попытки) |
| NFR-005 | Логирование | Все действия пользователей и ошибки логируются |
| NFR-006 | Graceful shutdown | Корректное завершение при получении SIGTERM/SIGINT |

### 14.3. Безопасность

| # | Требование | Описание |
|---|-----------|----------|
| NFR-007 | Токен бота | Хранится в переменной окружения `MAX_BOT_TOKEN` |
| NFR-008 | Валидация входных данных | Все пользовательские данные проходят валидацию |
| NFR-009 | Нет хранения персональных данных | Бот не сохраняет переписки на диск |

### 14.4. Развёртывание

| # | Требование | Описание |
|---|-----------|----------|
| NFR-010 | Контейнеризация | Dockerfile для запуска в Docker |
| NFR-011 | Конфигурация | Через переменные окружения и JSON-файлы |
| NFR-012 | Python-версия | 3.11+ |

## 15. Обработка ошибок

### 15.1. Таблица ошибок

| Код | Ситуация | Действие бота |
|-----|---------|---------------|
| E-001 | Ошибка API MAX | Логирование, retry. При 3 неудачах — сообщение пользователю: `⚠️ Произошла ошибка. Попробуйте позже.` |
| E-002 | Невалидная фамилия | Сообщение с описанием ошибки (см. раздел 6.2) |
| E-003 | Невалидный ИНН | Сообщение с описанием ошибки (см. раздел 11.2) |
| E-004 | Файл данных не найден | Логирование, сообщение: `⚠️ Данные временно недоступны.` |
| E-005 | Неизвестная команда/callback | Сообщение: `🤔 Не понимаю эту команду. Воспользуйтесь меню.` + показ главного меню |
| E-006 | Некорректный номер страницы | Перенаправление на первую страницу |
