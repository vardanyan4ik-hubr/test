## 1. Общее описание

### 1.1. Назначение системы

Чат-бот "Михалыч" — корпоративный помощник в мессенджере MAX для сотрудников компании Онланта. 

**Основные функции:**
- Авторизация пользователей
- Поиск информации о сотрудниках
- Доступ к корпоративным ресурсам
- Информирование по кадровым вопросам (отпуска, пропуска и т.д.)
- Предоставление Wi-Fi паролей
- Экспресс-отчеты по контрагентам
- Функции для руководителей

### 1.2. Целевая аудитория

- Все сотрудники компании Онланта
- Руководители отделов
- HR-специалисты
- СИБ (служба информационной безопасности)

### 1.3. Платформа

Мессенджер MAX (корпоративный мессенджер)

## 3. Функциональные требования

### 3.1. Модуль авторизации

#### 3.1.1. Сценарий: Первый запуск бота

**Триггер:** Пользователь вводит команду `/start` или открывает бота впервые

**Предусловие:** 
- Пользователь не авторизован в системе
- Пользователь имеет активный аккаунт в мессенджере MAX

**Основной поток:**

1. **Пользователь** вводит команду `/start`
2. **Система** проверяет статус авторизации пользователя
3. **Система** отправляет приветственное сообщение:

   ```
   👋 Привет, Я — *MAX-версия Михалыча*. Корпоративный чат-бот компании Онланта.
   
   🔐 Для начала работы мне нужно вас авторизовать.
   
   ✅ Нажмите кнопку «Начать», чтобы продолжить.
   ```

4. **Система** отображает inline-кнопку `"Начать"`
5. **Пользователь** нажимает кнопку `"Начать"`
6. **Система** инициирует процесс авторизации через MAX OAuth
7. **Система** получает данные пользователя:
   - user_id (уникальный идентификатор)
   - username (имя пользователя в MAX)
   - email (корпоративная почта)
   - full_name (ФИО)
8. **Система** сохраняет данные пользователя в БД
9. **Система** создает сессию пользователя
10. **Система** переходит к отображению главного меню

**Постусловие:**
- Пользователь авторизован
- Сессия создана
- Отображено главное меню

**Альтернативные потоки:**

**А1:** Ошибка авторизации
- На шаге 6, если авторизация не удалась
- **Система** отображает сообщение: "❌ Ошибка авторизации. Попробуйте снова через несколько минут или обратитесь в техподдержку."
- **Система** логирует ошибку
- Возврат к шагу 3

**А2:** Пользователь уже авторизован
- На шаге 2, если пользователь уже авторизован
- **Система** сразу переходит к отображению главного меню

#### 3.1.2. Структура данных авторизации

**Запрос на авторизацию (JSON):**

```json
{
  "action": "auth_start",
  "user_id": "max_user_12345",
  "timestamp": "2026-02-16T10:30:00Z"
}
```

**Ответ после успешной авторизации:**

```json
{
  "status": "success",
  "user": {
    "user_id": "max_user_12345",
    "username": "ivanov_ivan",
    "email": "ivanov@onlanta.com",
    "full_name": "Иванов Иван Иванович",
    "department": "IT",
    "position": "Разработчик",
    "is_manager": false
  },
  "session": {
    "session_id": "sess_abc123xyz",
    "created_at": "2026-02-16T10:30:15Z",
    "expires_at": "2026-02-16T18:30:15Z"
  }
}
```

**Ответ при ошибке авторизации:**

```json
{
  "status": "error",
  "error_code": "AUTH_FAILED",
  "error_message": "Не удалось авторизовать пользователя",
  "timestamp": "2026-02-16T10:30:00Z"
}
```

### 3.3. Модуль "Поиск сотрудников"

#### 3.3.1. Инициация поиска

**Триггер:** Нажатие кнопки `🔍 Поиск сотрудников` в главном меню

**Предусловие:**
- Пользователь авторизован
- Пользователь находится в главном меню

**Основной поток:**

1. **Пользователь** нажимает кнопку `🔍 Поиск сотрудников`
2. **Система** отправляет сообщение:

   ```
   🔍 *Поиск сотрудников*
   
   Введите фамилию сотрудника для поиска:
   ```

3. **Система** отображает кнопку `🏠 Главное меню`
4. **Система** переводит пользователя в состояние ожидания ввода фамилии
5. **Пользователь** вводит фамилию текстом
6. **Система** валидирует введенные данные
7. **Система** выполняет поиск в базе данных сотрудников
8. **Система** отображает результаты поиска

**Постусловие:**
- Результаты поиска отображены
- Пользователь может просмотреть информацию о сотрудниках

#### 3.3.2. Валидация ввода фамилии

**Правила валидации:**

1. **Длина:** от 2 до 50 символов (после удаления пробелов по краям)
2. **Допустимые символы:**
   - Буквы кириллицы (А-Я, а-я)
   - Буквы латиницы (A-Z, a-z)
   - Пробел (` `)
   - Дефис (`-`)
3. **Регулярное выражение:** `^[А-Яа-яA-Za-z\s\-]{2,50}$`

**Примеры валидных фамилий:**
- `Иванов`
- `Петров-Водкин`
- `О'Коннор`
- `Ван Дайк`

**Примеры невалидных фамилий:**
- `И` (слишком короткая)
- `Иванов123` (содержит цифры)
- `Петров@` (недопустимые символы)

#### 3.3.3. Обработка результатов поиска

**Случай 1: Найден один сотрудник**

**Система** отправляет сообщение с подробной информацией:

```

👤 *ФИО:* Иванов Иван Иванович
🏢 *Отдел:* IT-департамент

📞 *Телефон:* +7 (999) 123-45-67
📍 *Офис:* Москва, БЦ "Онланта", 5 этаж
```

**Случай 2: Найдено несколько сотрудников (2-10)**

**Система** отправляет список:

```
✅ *Найдено сотрудников: 3*

Выберите нужного сотрудника:
```

+ inline-кнопки для каждого сотрудника:
- `Иванов Иван Иванович (IT)`
- `Иванова Мария Петровна (HR)`
- `Иванов Петр Сергеевич (Финансы)`

**Случай 3: Найдено более 10 сотрудников**

**Система** отправляет сообщение:

```
⚠️ *Найдено слишком много совпадений (23)*

Уточните фамилию или введите полное ФИО для более точного поиска.
```

**Случай 4: Сотрудник не найден**

**Система** отправляет сообщение:

```
❌ *Сотрудник не найден*

Проверьте правильность написания фамилии и попробуйте снова.
```

### 3.4. Модуль "Ресурсы компании"

#### 3.4.1. Отображение ресурсов

**Триггер:** Нажатие кнопки `📚 Ресурсы компании` в главном меню

**Предусловие:**
- Пользователь авторизован
- В базе данных есть список корпоративных ресурсов

**Основной поток:**

1. **Пользователь** нажимает кнопку `📚 Ресурсы компании`
2. **Система** загружает список всех доступных ресурсов из БД
3. **Система** разбивает список на страницы (по 5 ресурсов на странице)
4. **Система** отправляет сообщение:

   ```
   📚 *Ресурсы компании*
   
   Страница 1 из N
   ```

5. **Система** отображает inline-кнопки:
   - 5 кнопок-ссылок на ресурсы (каждая кнопка ведет на URL ресурса)
   - Кнопка `⬅️ Предыдущая` (если текущая страница > 1)
   - Кнопка `Следующая ➡️` (если есть следующая страница)
   - Кнопка `🏠 Главное меню`

**Постусловие:**
- Отображена первая страница ресурсов
- Пользователь может перейти по ссылкам или переключать страницы

#### 3.4.2. Постраничная навигация

**Правила:**
- На одной странице — **максимум 5 ресурсов**
- Нумерация страниц начинается с 1
- Кнопка `⬅️ Предыдущая` отображается только если `current_page > 1`
- Кнопка `Следующая ➡️` отображается только если `current_page < total_pages`

**Сценарий: Переход на следующую страницу**

1. **Пользователь** нажимает кнопку `Следующая ➡️`
2. **Система** увеличивает номер текущей страницы на 1
3. **Система** обновляет сообщение с новой страницей ресурсов
4. **Система** обновляет кнопки навигации

**Сценарий: Переход на предыдущую страницу**

1. **Пользователь** нажимает кнопку `⬅️ Предыдущая`
2. **Система** уменьшает номер текущей страницы на 1
3. **Система** обновляет сообщение с новой страницей ресурсов

## 4. Нефункциональные требования

### 4.1. Производительность

| Параметр | Требование |
|----------|------------|
| Время отклика на команды | < 1 секунда |
| Время поиска сотрудника | < 2 секунд |
| Время формирования отчета | < 3 секунд |
| Максимальная нагрузка | 1000 одновременных пользователей |
| Доступность системы | 99.5% (uptime) |

### 4.2. Масштабируемость

- Система должна поддерживать до **5000 активных пользователей**
- Архитектура должна позволять горизонтальное масштабирование
- База данных должна поддерживать до **100 000 записей сотрудников**

### 4.3. Надежность

- **Резервное копирование:** ежедневное, с хранением за 30 дней
- **Отказоустойчивость:** автоматический перезапуск при сбоях
- **Логирование:** все действия пользователей и системные события

### 4.4. Безопасность

- Шифрование данных при передаче (TLS 1.3)
- Хранение паролей в зашифрованном виде
- Аутентификация через MAX OAuth 2.0
- Логирование всех запросов паролей Wi-Fi
- Разграничение прав доступа по ролям

### 4.5. Usability (Удобство использования)

- Интуитивно понятный интерфейс
- Время на обучение пользователя < 5 минут
- Кнопка "Главное меню" доступна из любого раздела
- Понятные сообщения об ошибках
- Подсказки для ввода данных

### 4.6. Поддерживаемые платформы

- **Мессенджер:** MAX (корпоративная версия)
- **Устройства:** десктоп (Windows, macOS, Linux), мобильные (iOS, Android)

## 7. Обработка ошибок

### 7.1. Типы ошибок

#### 7.1.1. Ошибки валидации

**Код:** `VALIDATION_ERROR`

**Примеры:**
- Некорректный формат фамилии
- Слишком короткий или длинный ввод
- Недопустимые символы

**Ответ пользователю:**

```
❌ *Ошибка ввода*

Фамилия должна содержать от 2 до 50 символов и состоять только из букв, пробелов и дефисов.

Попробуйте снова.
```

#### 7.1.2. Ошибки доступа

**Код:** `ACCESS_DENIED`

**Примеры:**
- Попытка доступа к разделу для руководителей
- Запрос недоступной информации

**Ответ пользователю:**

```
⛔ *Доступ ограничен*

У вас нет прав для выполнения этого действия.
```

#### 7.1.3. Ошибки системы

**Код:** `INTERNAL_ERROR`

**Примеры:**
- Недоступность базы данных
- Ошибка интеграции с внешней системой

**Ответ пользователю:**

```
⚠️ *Временная ошибка*

Не удалось выполнить запрос. Попробуйте снова через несколько минут.

Если проблема сохраняется, обратитесь в техподдержку.
```

#### 7.1.4. Ошибки данных

**Код:** `NOT_FOUND`

**Примеры:**
- Сотрудник не найден
- Контрагент не найден

**Ответ пользователю:**

```
❌ *Не найдено*

Не удалось найти информацию по вашему запросу.

Проверьте правильность введенных данных.
```

### 7.2. Логирование ошибок

**Формат лога ошибки:**

  "log_id": "error_12345",

## 8. Безопасность

### 8.1. Аутентификация и авторизация

- **OAuth 2.0** через MAX API
- Хранение токенов сессий в защищенном виде
- Автоматическое истечение сессий (8 часов неактивности)
- Проверка прав доступа перед каждым действием

### 8.2. Защита данных

- **Шифрование передачи:** TLS 1.3
- **Шифрование хранения:** AES-256 для чувствительных данных
- **Маскирование:** пароли Wi-Fi не логируются в открытом виде
- **Анонимизация:** логи не содержат персональных данных в открытом виде

### 8.3. Аудит и мониторинг

**Обязательное логирование:**
- Все запросы паролей Wi-Fi
- Доступ к финансовой информации (отчеты по контрагентам)
- Доступ к персональным данным сотрудников
- Изменения прав доступа

**Мониторинг:**
- Подозрительная активность (множественные неудачные попытки)
- Массовые запросы от одного пользователя
- Доступ в нерабочее время

### 8.4. Соответствие требованиям

- **GDPR:** право на удаление данных, доступ к своим данным
- **152-ФЗ (РФ):** защита персональных данных
- **Внутренние политики:** соответствие корпоративным стандартам безопасности
